# Cherry-Studio-BB v1.11.3 Release Notes

## 🎯 核心主题：界面微调 + 一次全面的代码审查与清理

这一版**不新增任何功能、不新增任何依赖、不改数据库结构**，只做三件事：把界面调顺、把查出来的 BUG 修掉、把多余的代码清干净。用户数据（聊天记录 / 助手 / 模型配置 / 知识库 / 便签 / 待办 / 闹钟）**完全兼容**。

---

## 🧹 本次改动

### 1. 界面：效率助手详情页改成「左 4 右 6」

- 「效率助手」详情页原来是左右各占一半：左边（闹钟 + 日历）、右边（便签/待办 + 音乐/FM）。右边内容更密、显得挤
- 现在**左边占 40%、右边占 60%**
- 实现上用的是 `2fr 3fr` 而不是直接写 `40% 60%`：网格之间有 **12px 的间隙**，写百分比是按容器宽度算的，会和间隙叠加导致**溢出**；用份数分配则是先扣掉间隙再按 2:3 分，正好是 40:60

### 2. 界面：删掉小程序里重复的第三组窗口按键

- 打开一个小程序后，标题栏右侧原先会多出一组「最小化 / 最大化 / 关闭」。这已经是**第三组**了：第一组在侧边栏右侧竖排，第二组是小程序自己的工具栏胶囊
- 现已删除，标题栏也不再为它预留 140px 的空位
- **窗口照样能关、能最大化、能最小化**（侧边栏那组保留，能力不受任何影响）

### 3. 修复：日历闹钟的未来日期显示"今天 X 分 Y 秒后"

- 旧逻辑只判断"日期是否已过去"，对**未来的日子**却拿"今天几点"去算差值 —— 等于给你一个假的"今天就要响"，误导性很强
- 现在**非当天的日历闹钟一律不显示倒计时**，只显示真正会在今天响的
- 已补两条单元测试守住这个行为（未来日期断言为"不显示"）

### 4. 修复：在页面渲染过程中修改全局状态（React 明令禁止）

- 小程序缓存重建时，会**在页面渲染的半路上**去修改 Redux 状态，可能引发界面卡顿、控制台告警甚至渲染死循环
- 现已挪到"渲染结束之后"执行，逻辑不变、隐患消除
- **顺带发现并修掉一个会漏内存的回归**：小程序缓存被整体重建时**忘了把新缓存告诉标签页服务**，会导致"关闭小程序的标签页"后清理失效、对应的网页进程残留在内存里不释放。这个问题是本版开发中真实存在并已修复的

### 5. 修复：两处定时器在组件卸载时没有清理

- **小程序网页**：加载完成后有一个延迟 100ms 的回调，组件卸载时没有取消 —— 会在组件已经销毁后继续执行
- **便签编辑器**：高亮闪烁的定时器在卸载时没有清理
- 两处都已补上清理

### 6. 修复：日历翻月可能多加 / 少加一年

- 旧写法在"更新月份"的函数内部又去调"更新年份"的函数。React 在某些情况下会**重复执行**这个函数，导致年份被多改或漏改
- 改为在点击事件里直接计算后再更新，行为确定、不再依赖 React 的调用次数

### 7. 修复：多个小程序切换时，延迟回调的定时器互相顶掉

- 延迟回调原先用的是**固定名字**，从一个切到另一个小程序时会把上一个的定时器覆盖掉，可能出现状态错乱
- 改为按小程序 ID 区分，各自独立

### 8. 清理：删除一整条「永远走不到」的顶部导航代码链路

- 全项目**没有任何地方**会把导航条切到顶部（导航位置一直是"左侧"），所以这套"顶部导航"分支永远不执行
- 已整条删除：3 个组件文件（`MinAppPage` / `MinimalToolbar` / `WebviewSearch`，合计 **962 行**）+ 1 条路由 + 其配套测试
- 这是**纯删除**，用户看到的界面与操作完全不变

### 9. 清理：删除各处没人调用的死函数

- webview 状态管理器 3 个、标签页服务 2 个、音乐播放逻辑 3 个（含配套测试）、电台读取 1 个、闹钟音量读取 1 个，以及播放器 hook 里两个没人用到的派生值
- 全部在删除前逐个确认过"全项目没有任何地方引用"

### 10. 清理：把抄了三遍的重复代码合并成一处

- 便签/待办的"今日活跃度 +1"和"列表预览文本截断"，原来便签、待办、列表各自写了一份，现统一收敛到一个公共文件
- 时钟补零函数 `pad2` 也改为复用已有实现
- 收益：以后改规则只改一处，不会出现"改了一处、漏了另一处"的不一致

### 11. 补充说明：闹钟的 `triggered` 字段

- 该字段现在只写不读（真正判断"今天是否已响"靠另一个键），但**保留不删** —— 因为老用户的数据库里已经存了这个字段，删掉会造成数据不兼容。已在代码与文档中加注说明
