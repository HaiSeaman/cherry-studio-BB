# Cherry-Studio-BB v1.8.4 Release Notes

## 🎯 核心主题：剪贴板排序/双保护/双击详情三项交互升级 + 全仓 6 模块并行审查与 20 处问题修复

本版本围绕**桌面助手 · 剪贴板**做了三处符合直觉的交互升级，并对整个仓库执行了一次**6 模块并行的全仓深度审查**——从高危运行时错误到内存泄漏、安全传输隐患、死代码逐项修复，同时核查确认全仓**无无用依赖**。

---

## ✨ 新功能与改进

### 1. 点击复制不再自动置顶

之前点击历史条目复制后，该条目会自动跳到第一位（同内容再次复制被当作"最新"刷新时间）。现在 **同内容再次复制保留原时间戳与列表位置**，除固定/收藏区在前外，其余严格按复制时间顺序排列，列表位置稳定不跳动。

### 2. 收藏与置顶双保护

【上限】（条数/天数修剪）与【清空】两条清理链路统一为：**收藏或置顶的消息永不清理，不受上限限制**。上限面板与清空确认弹窗文案同步明示。

### 3. 双击查看完整内容

列表文字最多显示 3 行的截断下，长内容看不见——现在**鼠标左键双击**任一记录会弹出小窗显示完整内容：

- 文本/色号：全文；富文本：保留换行的纯文本；图片：原图；文件：全部路径列表
- 窗内文字**可选中复制**，另有「复制 / 关闭」按钮
- 单击复制延迟 300ms 区分双击，避免「只想看详情却被覆盖系统剪贴板」

## 🐛 修复（全仓 6 模块并行审查，共 20 处）

### 高危（功能失效 / 数据丢失 / 崩溃）

| 问题 | 修复 |
|---|---|
| Hub `exec/invoke` 在打包产物中 **100% 失败**：worker 模板字符串内混入 TS 语法 `(error as ...)`，被 `eval` 当纯 JS 执行 | 改为纯 JS 写法，Node 实测通过解析（原 vitest 因拦截 worker 属假绿） |
| 桌面挂件打开 2 秒后**永久假未连接**（收到快照未清除超时） | 收到 snapshot/update 时清除超时定时器 |
| 剪贴板清空后再复制同内容 **无法重新入库** | 清空时重置"轮间变化闸门" |
| 发送消息后 500ms 二次清空，**吞掉用户立即开始的新输入** | 去掉多余的二次清空 |
| 翻译 / 检查 API 完成后 abort 条目永久残留（**模块级 Map 内存泄漏**） | 成功/失败/超时统一注销 |
| DXT 上传临时文件**永不删除**（每次泄漏一个文件） | try/finally 幂等清理 |

### 中危（边界 bug / 资源泄漏 / 安全）

- 划词助手反复开关 → 配置订阅累积 5 组回调 → `subscribe` 返回解绑函数、stop 统一解除 + 清空预载窗口队列
- 主窗口重建 → webview `onBeforeSendHeaders` 重复注册累积
- MCP 截图 / 网络抓取 / 滴滴请求无超时（页面挂起永久阻塞）→ 统一 30s 超时
- 滴滴 MCP 明文 `http://` + key 拼 URL → **HTTPS + header 传 key**
- MCP OAuth 超时永久挂起 / 端口占用 unhandled rejection
- 代理切换并发时静默丢失 → 最新请求获胜
- `abortTool` 移除伪造的 `null as IpcMainInvokeEvent`
- 迷你窗口监听清理误伤同通道 → 精准清理
- 消息列表静默搜索标志失效 / Markdown 流式渲染残留
- 图片捕获字体样式无限追加 → 覆盖 + finally 移除

### 死代码 / 依赖
- 删除零引用 `buildGenerateTextParams`、`extractFileContent` 及连带失效 import
- **全仓无用依赖：0 个**（逐包验证候选均有真实引用）
