# Cherry-Studio-BB v1.7.3 Release Notes

## 🎯 核心主题：修复生图助手「新建会话后生成结果看不见」· 三套工作台代码审计加固

这是一个**以修复为主的稳定性版本**。核心是解决了生图助手一个 P0 级缺陷：新建会话之后生成的图片在会话里看不到，但图片其实已经生成、也确实自动保存到了磁盘。同时对本版本涉及的**生图 / 动感视频 / 自动化**三套工作台做了一轮严格代码审计，修复了 4 类真实缺陷。

---

## 🐛 修复：生图助手新建会话后生成结果看不见

### 你遇到的现象

- 点击「新建话题」之后，在新会话里生图看不到任何结果
- 强行删除会话再试，新生成的图片依然不出现
- 但图片确实生成出来了，也确实自动保存到了默认目录里

### 真正的原因

**不是生成链路坏了，而是界面拿到了一份「过期的数据」。**

应用把「当前助手」这个对象存进了组件内部状态，成为一份快照。而新建会话时，Redux 里的助手对象会被替换成新版本，**快照里的会话列表却永远停在打开应用那一刻**。生图工作台又恰恰用这份列表来判断「当前会话是否属于这个助手」——于是每一个新建的会话都被误判成「不属于本助手」，内容区被强制清空，输入栏每次生成都会再偷偷建一个新的空会话。

结果就是：图片照常生成、照常落盘，但写进了一个你当前根本没在看的会话里。

```
新建话题 → Redux 里已有，快照里没有
        → 守卫判定「不属于本助手」→ 内容区被迫置空
        → 输入栏拿到空会话 → 每次生成都再造一个孤儿会话
        → 图片照常落盘（保存回调与界面状态无关）→ 你在当前会话里永远看不到
```

> 这也解释了那个最让人困惑的现象——**历史列表里能看到这些会话，点进去却是空的**。因为列表组件读的是实时数据，内容区读的是快照，两边不是同一份数据。

### 修复方式

- **根治**：`HomePage` 不再保存助手对象，只保存「当前助手 id」，助手对象一律从 Redux 实时派生 —— 快照这一层被彻底移除。
- **防御**：新增统一的实时数据约定（`useLiveAssistant` / `resolveValidTopicId`），生图、动感视频、自动化三套工作台以及两个历史列表全部改用实时数据，杜绝同类问题再次发生。

### 顺带修掉的一个老问题

会话记录在数据库中缺失时（例如数据被外部清理过），内容区会**永远转圈**。现已区分「正在加载」与「记录确实不存在」，后者会明确提示「会话不存在或已被删除」。

## 🛡️ 三套工作台代码审计加固

按严格 review 流程对生图 / 动感视频 / 自动化工作台做了正确性与错误处理审计：

| 问题 | 说明与修复 |
|---|---|
| **生成期间新建会话会吞掉结果**（4 处） | 「新建话题」按钮在生成时是禁用的，但 **`new_topic` 快捷键走的是同一入口、绕过了这个禁用**。生成途中切到新会话，在途结果仍会写回旧会话，用户眼前却是全新的空会话 —— 表现与本版本的 P0 完全一致。四处入口统一加了拦截，两个「+」按钮也补上了禁用于置灰 |
| **视频「生成中」状态无法跨组件共享** | 该状态原本只在输入栏内部，历史列表拿不到，无法同步禁用。已提升到工作台层统一持有并下发（生图侧本就走全局状态，无需改造） |
| **删除会话时产生幽灵记录**（2 处） | 删除当前会话后，代码会造一个随机 id 的假会话顶上去（不在数据库、也不在状态里），还会往消息缓存写入永远清理不掉的条目。改为从剩余会话里挑下一个；没有剩余就交给归属守卫判空态。两处同时补上了失败提示 |
| **自动化工作台 5 处操作无失败处理** | 启用/暂停、立即运行、复制、删除、保存任务这 5 个操作一旦底层调用失败，既没有任何提示，也会在控制台留下未处理的异常。现全部补上错误提示与日志记录 |

**审计中核实为「不是问题」、避免误改的项**：图生图时界面显示「1 张」而底层参数仍是多选值（图生图走的是另一个接口分支，实际就是 1 张）；视频进度更新整体覆盖元数据（生成期该字段只有进度文案，无损失）；图片自动保存不会重复落盘或重复占用内部存储。

## 📦 安装与升级

Windows 64 位用户请下载下列任一产物覆盖安装，**数据自动保留**：

- `Cherry-Studio-BB-1.7.3-x64-setup.exe`（安装版，推荐）
- `Cherry-Studio-BB-1.7.3-x64-portable.exe`（便携版，免安装）

### 升级后建议验证

1. 进入**灵感生图**助手，点「新建话题」新建一个会话
2. 输入提示词、选择绘画模型，点击「生成图片」
3. 图片应**直接出现在当前会话里**（而不是只出现在磁盘目录）
4. 左侧「生成历史」里应能看到该会话的缩略图与张数，点进去内容一致

本次更新不涉及数据迁移，原有会话与图片均不受影响。
