# Cherry-Studio-BB v1.11.4 Release Notes

## 🎯 核心主题：一次彻底的「体检 + 治病 + 减肥」

这一版**不新增功能、不新增依赖、不改数据库结构**。做的是一次全仓深度审查：把潜伏的 **18 个真实 BUG** 修掉（其中 2 个会直接丢数据、2 个会让程序卡死）、把 **23 个没人调用的死函数/常量**、**3 个随之无用的类型**和 **2 个死文件**删掉、把 **3 处抄了两遍的代码**合并成一处。

用户数据（聊天记录 / 助手 / 模型配置 / 知识库 / 便签 / 待办 / 闹钟 / 打卡）**完全兼容**，覆盖安装即可。

## 🔴 会丢数据的两个 BUG（最优先修）

### 1. 恢复备份时，可能把「现有数据」和「备份」一起删掉

**你遇到的现象**：点了「从备份恢复」，程序重启后数据全没了，连备份文件也找不回来。

**为什么**：旧流程是「先删掉现有数据目录 → 再把备份改名放进去」。如果改名这一步失败（跨磁盘、文件被占用、权限不足），代码的出错处理又会**把备份也删掉** —— 结果两边都没了。

**现在怎么做**：
1. 先把现有数据目录改名成 `xxx.old`（暂存，不删）
2. 再把恢复数据改名到位
3. 只有第 2 步成功，才删掉 `xxx.old`
4. 如果第 2 步失败，**自动把 `xxx.old` 改回去**，程序照常能用原数据启动；恢复数据也原样保留，可以重试

> 一句话：**先给旧数据留后路，绝不先删。**

### 2. 剪贴板会「永久漏记」你复制的内容

**你遇到的现象**：复制了一段文字，剪贴板历史里就是没有；再复制同样的内容还是不出来。

**两个原因**：
- 程序先记下「剪贴板序号」，再去读内容。如果读取那一刻剪贴板正被密码管理器占用而报错，序号已经记下了 → **下次同样的内容会被判定成"没变过"直接跳过**，永久漏掉
- 删掉某条历史、或触发容量淘汰后，程序没有重置「这内容我见过」的标记 → 你再复制同样的内容，**永远进不来**

**现在怎么做**：读取**全部成功之后**才记录序号；删除和淘汰时一并重置去重标记。

## 🟠 会让程序卡死 / 空转的两个 BUG

### 3. 知识库切块可能死循环，直到内存爆掉

**你遇到的现象**：在知识库设置里把「重叠度」调得比「切块大小」还大（界面允许：切块最小 256，重叠最大 1024），然后导入文件或重建索引 —— **页面直接卡死**，只能强杀进程。

**为什么**：切块时如果重叠量覆盖了整个块，下一块的起点会退回到原处甚至更前，于是永远在处理同一段文字，内存被无限填满。

**现在怎么做**：
- 参数入口先做安全钳制：重叠度最多等于「块大小 − 1」
- 再加一道硬保险：**每一轮至少前进一行**，无论参数怎么配都不会原地打转

> 就算你把参数调得很离谱，最多是切块质量差一点，**不会再卡死**。

### 4. 自动化任务在开机时「假装执行」

**你遇到的现象**：设了定时任务，开机后看到任务状态是「运行中」，等很久才变成「超时失败」，实际什么都没做。

**为什么**：主程序在界面**还没准备好接收指令**的时候就把任务派发出去了，事件无人接，任务却被标记成「运行中」，只能等 10 分钟看门狗判超时。

**现在怎么做**：加了一个「界面已就绪」的握手。界面挂好监听后回一句「我准备好了」，主程序才开始派发任务；没就绪时任务保持「待触发」，就绪瞬间立刻补上。

## 🧹 删掉的死代码

所有删除项都先做了「全项目引用计数 + 转发导出检查 + 命令行调用检查」三重确认，**没有一处是凭感觉删的**。

| 删除项 | 依据 |
|---|---|
| `pages/launchpad/`（启动台页面，195 行）与路由 | 全项目没有任何入口：侧边栏、托盘、快捷键、设置页、引导页全查过 |
| `scripts/scan-unused-deps.mjs` | 零调用；而且它名不副实，实际是「编译 + 打包」脚本，功能与 `build:win` 完全重复 |
| **23 个零引用导出**（函数/常量） | 全项目（含测试、含 `export *` 转发）只出现 1 次，就是定义本身 |
| 3 个随之无用的类型 | `CoreProviderId` / `ImageFileMetadata` / `PdfFileMetadata`，仅被上面那些死函数与死代码引用 |
| webview 状态管理器里的监听器机制 | 全项目**零个订阅者**，只剩一套永远不会被调用的回调链 |
| 消息过滤工具里一段空的 `@deprecated` 注释 | 注释下面已经没有代码了 |
| 聊天里 AI 导航按钮的 10 条无效路由标签 | 指向 `/store`、`/agents`、`/launchpad`、`/settings/about` 等**根本不存在的页面** |
| 启动台相关的 3 组文案 | 页面已删，文案没人读 |

**依赖包一个都没删**：初筛出 21 个"看起来没用"的包，逐个核对后全部是误报 —— 11 个是类型声明包（`@types/*`），其余是通过 `package.json` 命令调用的工具，还有一个是在 CSS 里 `@import` 的。

## ⬆️ 升级说明

- 直接覆盖安装即可，**不需要重新登录、不需要重新配置任何服务商或 API Key**
- **无数据库结构变更**：聊天记录 / 助手 / 模型配置 / 知识库 / 便签 / 待办 / 闹钟 / 打卡全部兼容
- 侧边栏里原本就没有「启动台」入口，所以删掉它对界面没有任何影响

### 想验证修复效果

1. **备份恢复**：做一次备份 → 恢复 → 确认数据回来了，且备份文件还在
2. **剪贴板**：复制一段文字 → 在历史里删掉它 → 再复制同一段 → 应该重新出现
3. **知识库**：把重叠度调到比切块大小更大，导入一个文件 → 不再卡死
4. **倒计时**：让一个闹钟正在响，同时让倒计时归零 → 关掉倒计时后，闹钟会重新响
5. **FM 电台搜索**：输入关键词后立刻清空 → 不会再一直转圈
