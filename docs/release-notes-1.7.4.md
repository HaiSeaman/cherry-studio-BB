# Cherry-Studio-BB v1.7.4 Release Notes

## 🎯 核心主题：修复打卡月历「9 月及之后全部错乱」P0 缺陷 · 打卡功能二轮代码审计加固

本版本是一个**以修复为主的稳定性版本**，核心是解决了打卡（Habit Tracker）功能页一个 P0 级缺陷：**8 月份打卡一切正常，但一翻到 9 月，所有日期全部错乱、格子消失、无法点击打卡，整个 UI 排版崩塌**。同时对打卡模块做了完整的两轮代码审查，修复了若干真实缺陷并补齐了边界校验。

---

## 🐛 修复：打卡月历 9 月及之后月份整体错乱

### 你遇到的现象

- 8 月一切正常，日期小方块可正常点击打卡
- 切到 **9 月**后，所有日期错乱、找不到打卡的地方、小方块消失
- 整个排版全部错乱，UI 界面变形

### 真正的原因

**不是数据问题，而是月历网格的 CSS 写死了一个数字。** 月历的日期列数量被硬编码成了 **31 列**，但每个月实际渲染的天数不同：

- **8 月有 31 天** → 每行格数恰好与 31 列严丝合缝 → 一切正常
- **9 月只有 30 天** → 每行末尾空出一列，由于网格使用自动放置，**下一行的第一个格子被吸上来填补空位**，于是一行错一列、逐行级联错位 → 表头与格子全部对不上、连续列落空、格子被挤进名称列看不见

其实 **2 月（28 天）、4 月 / 6 月 / 11 月（30 天）** 全部会触发，只是你之前一直停留在 31 天的月份没有发现。

> 另外发现一处浏览器会直接丢弃的非法 CSS（`min(1fr, 88px)` —— fr 单位不允许进 `min()` 数学函数），它让月历行的弹性高度从未生效，加剧了排版劣化，一并修复。

### 修复方式

- **根治**：网格列数改为**随当月实际天数动态生成**（28~31 天都精确对齐），彻底消除错位
- **防御**：修复非法 CSS 行高写法，弹性布局真正生效；新增回归测试锁定「列数 = 当月实际天数」，未来任何月份都不会再错

### 顺带修掉的两个老问题

1. **「今天」被跳过时，当前连续天数少算 1 天**：跳过日应当不断卡、同样计 1 天，现在与统计口径完全一致
2. **习惯创建日之前的日期被误标为「漏卡」警示且可点击打卡**：这些天习惯还不存在，不是漏卡——现在创建日之前的格子自动锁定，不再显示红色警示、也不能误打

## 🛡️ 打卡模块二轮代码审查加固

按严格 review 流程对打卡模块全部代码做了正确性 / 边界 / 数据安全审计：

| 问题 | 说明与修复 |
|---|---|
| **JSON 备份导入零校验（高危）** | 导入是**替换式写库（不可逆）**，但旧代码对行数据没有任何校验——损坏的备份（如日期 `2026-9-1` 非补零格式、非法状态字段）会直接污染整库日历与统计且无法撤销。现新增 `parseHabitsBackup` 行级校验：字段 schema / ISO 补零日期 / 状态枚举 / **引用完整性**（杜绝指向不存在习惯的孤儿记录），任何一行不合法都在写入前整体拒绝 |
| **当前连续口径偏差** | 今天被标记「跳过」时连续天数少计 1 天，与「跳过不断卡」口径不一致，已修复并加测试 |
| **创建日之前显示漏卡** | 习惯创建前的日子被渲染为红色「漏卡」虚线且可点击，属误导性 UI，已锁定 |
| **备份文件名时区差** | 导出文件名用 UTC 日期，东八区晚间会差一天，改为本地时区 |

**审查中核实为「不是问题」、避免误改的项**：日历纯函数、统计口径、Dexie 表结构与复合主键、React Hooks 顺序、`useLiveQuery` 自动刷新机制均正确，未做无效改动。

## 📦 安装与升级

Windows 64 位用户请下载下列任一产物覆盖安装，**数据自动保留**：

- `Cherry-Studio-BB-1.7.4-x64-setup.exe`（安装版，推荐）
- `Cherry-Studio-BB-1.7.4-x64-portable.exe`（便携版，免安装）

### 升级后建议验证

1. 进入**打卡** TAB，翻到 9 月（或其他非 31 天月份），整月日期应整齐对齐
2. 今天的格子应高亮可点击，点击即可打卡；明天及以后不可点
3. 翻到创建习惯之前的月份，该习惯的格子应为锁定态、无红色漏卡警示
4. 习惯管理 → 导入一份损坏的 JSON 备份，应提示「导入失败」且原有数据不受影响

本次更新不涉及数据迁移，原有打卡数据均不受影响。
