# 02 · 整体架构

## 1. 三进程架构总览

Cherry Studio 采用 Electron 经典三进程模型，另加多个辅助窗口：

```
┌──────────────────────┐
│   Main 主进程         │  Node.js 环境，拥有全部系统能力
│   src/main/index.ts   │  窗口/托盘/文件系统/MCP/备份/快捷键…
└─────────▲────────────┘
          │ ipcMain.handle(IpcChannel.X, handler)   ← invoke/request-response
          │ webContents.send(...)                   ← 主→渲染主动推送
┌─────────┴────────────┐
│   Preload 预加载       │  src/preload/index.ts
│   contextBridge 暴露   │  安全桥：把 IPC 通道以白名单方式暴露给渲染层
└─────────▲────────────┘
          │ window.api.* / invoke(IpcChannel.X, ...)
┌─────────┴───────────────────────────────────────────┐
│   Renderer 渲染层（5 个 HTML 入口）                    │
│   ├─ index.html            主窗口（React 应用）        │
│   ├─ miniWindow.html       迷你快速助手窗               │
│   ├─ musicWidget.html      音乐挂件窗                  │
│   ├─ selectionToolbar.html 划词悬浮工具条               │
│   └─ selectionAction.html  划词动作弹窗                 │
└─────────────────────────────────────────────────────┘
```

- 主窗口 `webPreferences.webviewTag: true`（`WindowService.ts:232`），MinApp webview 使用独立 `persist:webview` partition；不向远程不可信 webview 注入 preload。
- 外链统一经 `isSafeExternalUrl` 校验后转 webview 或 `shell.openExternal`。

## 2. 启动流程（主进程）

入口 `src/main/index.ts`：

1. **副作用引导**：首先 `import './bootstrap'`（打包环境初始化数据目录、支持命令行参数触发的 appData 迁移，Windows 下由主进程复制被占用目录）；再 `import '@main/config'`（dev 时 userData 加 `Dev` 后缀、定义 titleBarOverlay 颜色、设置 `CHERRYAI_CLIENT_SECRET`）。
2. **就绪前配置**：按配置禁用硬件加速；Windows 禁用窗口动画；Linux Wayland 启用 `GlobalShortcutsPortal`；注册 `Document-Policy` 响应头；生产模式捕获 `uncaughtException/unhandledRejection`。
3. **单实例锁**：`app.requestSingleInstanceLock()` 失败即退出。
4. **`app.whenReady()` 启动序列**：
   ```
   versionService.recordCurrentVersion()
   → initWebviewHotkeys() → AppUserModelId → 按"启动到托盘"隐藏 Dock
   → BackupManager.handleStartupRestore()   ★ 最高优先级：备份恢复标记检查
   → windowService.createMainWindow()
   → 懒创建音乐/便签挂件窗 → new TrayService() → setupApplicationMenu()
   → powerMonitorService.init() → automationService.init()（30s tick 定时调度）
   → 提取 rtk 二进制 → registerShortcuts(mainWindow)
   → await registerIpc(mainWindow, app)     ★ IPC 注册中心
   → setupAppImageDeepLink() → dev 安装 DevTools
   → initSelectionService() / initScreenshotService()
   ```
5. **协议**：`registerProtocolClient(app)` 注册 `cherry://`（打包产品为 `cherrystudio://`）深链，处理 `open-url`/`second-instance`/argv。
6. **退出清理**：`before-quit` 清理 selection/screenshot 服务；`will-quit` 中 `mcpService.cleanup()` 并 flush 日志。

## 3. IPC 通信机制

### 注册模式

全部通道注册集中在 **`src/main/ipc.ts` 的 `registerIpc(mainWindow, app)`**（792 行）：

- 内部实例化 `BackupManager / ExportService / ObsidianVaultService / DxtService / NotificationService` 等；
- 数百个 `ipcMain.handle(IpcChannel.<域>_<动作>, handler)`，多数直接 `.bind(service)` 绑定到服务方法；
- 末尾调用 `storeSyncService.registerIpcHandler()` 与 `SelectionService.registerIpcHandler()`。

### 通道契约

- 通道名唯一真源是 **`packages/shared/IpcChannel.ts` 的 `IpcChannel` 枚举**（数百项，按域分组：`App_*`、`Mcp_*`、`File_*`、`Backup_*`、`Automation_*`、`Selection_*`、`MusicWidget_*`、`Theme_*`、`StoreSync_*` 等），经 preload 层暴露给 renderer。
- 少量流式场景用 `ipcMain.on`（如音乐挂件 `MusicWidget_MsgFromWidget/MsgToWidget`、`Theme_FromRenderer`）。
- 主→渲染主动推送用 `webContents.send`：`App_SaveData`（关机通知）、`ThemeUpdated`、`StoreSync_BroadcastSync` 等。
- 对 webview 相关通道做 `getType() !== 'webview'` 校验，防止误关真实窗口。

### 渲染层调用方式

渲染层通过 preload 注入的 `window.api` 或封装的 `invoke(IpcChannel.X, payload)` 发起请求；Redux store 就绪后会回发 `invoke(IpcChannel.ReduxStoreReady)` 通知主进程。

## 4. 核心数据流：一次 AI 对话

```
用户输入 (pages/home/Inputbar)
→ useMessageOperations / messageThunk.sendMessage()   [store/thunk/messageThunk.ts]
→ ApiService.fetchChatCompletion()                    [services/ApiService.ts]
→ renderer aiCore.AiProvider.completions()            [aiCore/AiProvider.ts]
   ├─ buildPlugins(): 组装业务插件数组                  [plugins/PluginBuilder.ts]
   └─ createExecutor(providerId, settings, plugins)   [@cherrystudio/ai-core]
        └─ RuntimeExecutor.streamText()                Vercel AI SDK v6
← AiSdkToChunkAdapter 把 SDK 流事件适配为内部 Chunk 回调
← messageStreaming/BlockManager 处理流式分块、平滑输出
← 节流落库 throttledBlockUpdate → Dexie(message_blocks/topics)
```

工具调用与联网搜索在插件层完成：MCP 工具经 `promptToolUsePlugin`（XML prompt 工具模式）或原生 Function Call；搜索经 `providerToolPlugin('webSearch')` 注入各 provider 原生搜索能力。

## 5. 多窗口协作

| 窗口 | 创建方 | 协作机制 |
|---|---|---|
| 主窗口 | `WindowService.createMainWindow()` | 标准 Redux + StoreSync |
| 迷你助手窗 | `createMiniWindow()/showMiniWindow()` | `quoteToMainWindow(text)` 引用文本到主窗 |
| 音乐挂件窗 | `WidgetWindowController` | `widgetBridge` 消息桥 + `MusicWidget_*` IPC |
| 划词工具条/动作弹窗 | `SelectionService`（弹窗池预创建+栈式复用） | `Selection_*` IPC + 剪贴板 |

跨窗口 Redux 同步：渲染层 `storeSyncService.createMiddleware()` 中间件把 `syncList:['assistants/','settings/','llm/','selectionStore/']` 中命中的 action 广播到其他窗口（带 `fromSync` 元数据防死循环）。主进程侧的旧版 `ReduxService`/`StoreSyncService` 已 deprecated。
