# 06 · 数据存储与状态管理

## 1. Redux Toolkit + redux-persist（渲染层）

### Store 组织（`src/renderer/src/store/index.ts`）

- `configureStore` 组合约 18 个 reducer；持久化配置：`persistReducer({ key:'cherry-studio', version:4, migrate, blacklist:[runtime, messages, messageBlocks, tabs, toolPermissions, paint] })`。
- 历史迁移函数已清理：`migrate.ts` 只保留覆盖 v0~v4 净效果的纯函数（曾多达 216 个）。
- rehydrate 完成后 dispatch `mergeDefaults()` 补齐新增快捷键，并 `invoke(IpcChannel.ReduxStoreReady)` 通知主进程。
- 跨窗口同步：`storeSyncService.createMiddleware()` + `setOptions({ syncList:['assistants/','settings/','llm/','selectionStore/'] })`，广播 action 带 `fromSync` 元数据防死循环。
- 导出类型化 hooks `useAppDispatch/useAppSelector/useAppStore`，并把 store 挂到 `window.store`。

### Slice 清单

| Slice | 说明 |

### 异步逻辑中枢

无 redux-saga/thunk 中间件堆叠，异步集中在 **`store/thunk/messageThunk.ts`（~1500 行）**：
`sendMessage:463`、`resendMessageThunk`、`regenerateAssistantResponseThunk`、`loadTopicMessagesThunk`、`initiateTranslationThunk`、`saveMessageAndBlocksToDB`、节流落库 `throttledBlockUpdate` 等 —— 是消息收发与持久化的唯一枢纽。

## 2. Dexie / IndexedDB（渲染层本地库）

单文件库 **`CherryStudio`**（`src/renderer/src/databases/index.ts:28`，`chromeTransactionDurability:'strict'`），当前版本 **13**，升级脚本在 `databases/upgrades.ts`（upgradeToV5/V7/V8/V13）：

| 表 | 用途 |
|---|---|
| `files` | 文件附件元数据（id/name/path/size/ext/count…） |
| `topics` | 聊天话题（id 主键，messages 数组；可选 type/name/updatedAt 区分绘画会话） |
| `settings` | K-V 杂项设置 |
| `quick_phrases` | 快捷短语 |
| `message_blocks` | 新消息模型的块存储（索引 messageId、file.id）—— 消息内容拆块 |
| `music_tracks`(++id, &filePath 唯一) / `music_folders`(&path) / `radio_favorites`(&url) | v11 音乐三表 |
| `hub_notes` / `hub_todos`(++id,status) / `hub_alarms`(++id) / `hub_day_notes`(++id,date) / `hub_activity`(&date) / `hub_note_history`(++id,noteId) | v12 闹钟便签六表 |
| `habits`(id, order, archived) / `habit_records`([habitId+date], date) | v13 打卡两表（习惯定义 + 每日打卡记录，复合主键保证幂等；`date` 索引供月历按区间查询） |

> 打卡统计口径（当前连续/最长连续/完成率/EMA 强度指数/星期分布/自然年统计）全部收敛于 `pages/habits/services/stats.ts` 纯函数模块，口径规则见 `docs/superpowers/specs/2026-08-28-habit-tracker-design.md#44-统计口径实现规则含-skip-处理`；**跳过(skip)日不算应打卡日、不断卡**，三处口径保持一致。
>
> 打卡 JSON 导入是**替换式写库（不可逆）**，入口必须经过 `habitService.parseHabitsBackup` 行级校验（schema / ISO 补零日期 / 状态枚举 / 引用完整性），损坏文件在写入前抛错拒绝；v1.7.4 起该函数为唯一校验出口。月历「漏卡」判定只作用于创建日（`createdAt`）之后且今天之前的日子，创建前格子锁定不可打卡。

已废弃表：`knowledge_notes`(v10 移除)、`translate_history` / `translate_languages`(v10 移除)。

主进程侧无 SQLite 业务库；文件二进制存于应用数据目录（FileStorage 服务管理），元数据在 Dexie。

## 4. 备份与恢复（BackupManager）

三种目标端：**本地目录 / WebDAV / S3**。

```
备份：backup() → backupToLocalDir | backupToWebDAV | backupToS3 （进度上报）
恢复：restore() → restoreFromLocalBackup | restoreFromWebDAV | restoreFromS3
启动：handleStartupRestore():84 —— 最高优先级检查恢复标记，必要时先于窗口创建执行
重置：resetData():763
辅助：checkConnection / checkS3Connection / createDirectory / listLocalBackupFiles / delete*
```

设置页 DataSettings 提供对应 UI；云端凭据存于 electron-store。

## 6. 状态陷阱：assistant 快照 vs Redux 实时对象（v1.7.3 收口）

### 问题

`assistants` slice 的 `addTopic` / `removeTopic` 经 Immer 会**换掉 store 里的 assistant 对象引用**。若组件把 assistant 存进 `useState`（或由父组件以快照形式下发），该副本的 `topics` 会**永远停在挂载那一刻**。

v1.7.3 之前 `HomePage` 正是 `useState(assistants[0])`，而 `PaintWorkspace` 又用 `assistant.topics` 做会话归属守卫，于是：

```
新建话题 → Redux 已含该话题，但快照里没有
        → 守卫判定「不属于本助手」→ validTopicId = null
        → 内容区空态，输入区每次生成都再建一个孤儿话题
        → 图片照常落盘，但用户在当前会话里永远看不到
```

这与「话题列表能看到、点进去却空白」并存——因为 `PaintHistoryList` 当时已自行回 Redux 取数，两者数据源不一致。

### 约定（强制）

1. **只存 id，不存对象**：`HomePage` 的 state 只保留 `activeAssistantId`，`activeAssistant` 用 `useMemo` 从 Redux 派生（兜底顺序：`find(id)` → 路由带来的 `state.assistant` → 模块级 `_activeAssistant` → `assistants[0]`）。
2. **凡读 `assistant.topics` 先过 `useLiveAssistant`**（`hooks/useAssistant.ts`）：
   - `resolveLiveAssistant(assistants, assistant)` — 纯函数，按 id 取最新助手，取不到回退入参（便于单测）
   - `useLiveAssistant(assistant)` — 上面的 hook 版，selector 返回 store 内对象，引用稳定、不会触发额外渲染
   - `resolveValidTopicId(assistant, activeTopic)` — 会话归属守卫，两个 Workspace 共用；不命中一律返回 `null`
3. **生成期间禁止切换/新建会话**（生图 + 视频四处入口）：在途生成的结果始终写回**发起时的** topic，一旦期间切到新会话，用户眼前就是空会话，表现与「生成失败」无异。按钮需 `disabled`，且 `new_topic` 等快捷键入口必须单独加 `isGenerating` 拦截（`useShortcut` 不受按钮 `disabled` 约束）。
4. **不要用 `getDefaultTopic()` 当「重置」哨兵**：它返回随机 id 的幽灵话题（不在 db、不在 Redux），会污染 `newMessage` slice。删除当前会话时应从**剩余 topics** 里挑下一个；没有剩余就不动 `activeTopic`，交给归属守卫判空态。

### 排查提示

遇到「数据已落盘/写入成功，但 UI 不显示」类问题，沿 `落盘回调 → Dexie 写入 → Redux → 组件守卫 → 渲染` 逐层定位，**优先怀疑同一份数据存在两个来源（快照 vs Redux）**。相关回归测试：`src/renderer/src/pages/paint/__tests__/workspaceTopicGuard.test.ts`（用真实 reducer 驱动纯函数守卫）。
