# 05 · AI 核心体系

## 1. 总体分层

```
业务层 (renderer)                    框架层 (workspace 包)
┌─────────────────────────┐   ┌──────────────────────────────────┐
│ messageThunk.sendMessage │   │  @cherrystudio/ai-core           │
│   ↓                      │   │  (packages/aiCore, v2.0.1)       │
│ ApiService.fetchChat...  │   │   基于 Vercel AI SDK v6 (ai@6.x)  │
│   ↓                      │   │                                  │
│ aiCore/AiProvider        │──▶│   createExecutor() → RuntimeExecutor│
│   buildPlugins()         │   │   PluginEngine + 插件体系          │
│   AiSdkToChunkAdapter    │   │   ExtensionRegistry + Provider    │
└─────────────────────────┘   └──────────────────────────────────┘
```

渲染层 `src/renderer/src/aiCore` 是**业务编排层**：不直接碰 AI SDK，把应用 Provider/Model 转为配置、组装业务插件数组后交给 `@cherrystudio/ai-core` 执行。Provider 配置逻辑（`providerToAiSdkConfig` 等）目前仅存在于渲染层（`aiCore/provider/providerConfig.ts`），主进程无对应 aiCore 目录；若在主进程新增 AI 调用需注意 URL 格式化等共享逻辑应放回 `packages/shared/utils/api/`。

## 2. packages/aiCore（@cherrystudio/ai-core）

独立发布的 npm 包（tsdown 构建）。依赖：peer `ai`、`@ai-sdk/google`、`@ai-sdk/openai`；直接 `@ai-sdk/{anthropic,azure,deepseek,openai-compatible,provider,provider-utils,xai}`、`@openrouter/ai-sdk-provider`。

### 2.1 执行器架构

- **`RuntimeExecutor`**（`core/runtime/executor.ts:30`）：核心执行器，内部持有 `PluginEngine` 和单 provider `createProviderRegistry`。方法：`streamText / generateText / generateImage / embedMany`；model 为字符串 modelId 时自动注入 `_internal_resolveModel` 插件解析为模型对象（优先 extension 的 `modelResolver`，否则走 registry），并强制 V3 模型校验（`isV3Model`）。静态工厂 `RuntimeExecutor.create()` / `.createOpenAICompatible()`。
- **便捷工厂**（`core/runtime/index.ts:23-115`）：`createExecutor(providerId, options, plugins)` 先经 `extensionRegistry.createProvider()` 创建 provider 实例再构建 executor；另有一步式顶层封装 `streamText/generateText/generateImage/embedMany/createOpenAICompatibleExecutor`。
- **`PluginEngine`**（`core/runtime/pluginEngine.ts`）：按 `enforce: 'pre'|'post'` 排序插件、驱动钩子生命周期、收集流 transform 并统一应用 LanguageModelMiddleware。
- **错误体系**（`core/errors/index.ts`）：`AiCoreError / ModelResolutionError / ParameterValidationError / PluginExecutionError / RecursiveDepthError / TemplateLoadError`；runtime 另有 `ImageGenerationError / ImageModelResolutionError`。

### 2.2 Provider Extension 体系

内置 provider 定义于 `core/providers/core/initialization.ts:249`（`coreExtensions`），模块加载时 `extensionRegistry.registerAll(coreExtensions)` 幂等注册：

| Extension | aliases | variants | 特性 |
|---|---|---|---|
| openai | `openai-response` | `-chat` | webSearch 工具 |
| anthropic | `claude` | — | webSearch + urlContext |
| azure | `azure-openai` | `-responses`、`-anthropic` | 默认 chat 模式包装 |
| google | `google-ai`/`gemini` | — | googleSearch + urlContext |
| xai | `grok` | `-responses` | webSearch/xSearch |
| deepseek | — | — | — |
| openrouter | `tokenflux` | — | webSearch 走 providerOptions |
| openai-compatible | — | — | 通用兜底 |
| cherryin | — | `-chat` | 自研 provider（`core/providers/cherryin/cherryin-provider.ts`） |

机制：`ProviderExtension.ts` 声明 name/aliases/variants/create/toolFactories；`ExtensionRegistry.ts` 全局注册表支持变体 ID 解析、`resolveToolCapability`、`getModelResolver`；类型（`CoreProviderSettingsMap`、`ProviderId` 等）全部从 coreExtensions 自动推导保证安全。

### 2.3 插件体系

插件接口 `AiPlugin`（`core/plugins/types.ts:68`），钩子四类：
- First：`resolveModel` / `loadTemplate`
- Sequential：`configureContext` / `transformParams` / `transformResult`
- Parallel：`onRequestStart` / `onRequestEnd` / `onError`
- Stream：`transformStream`

上下文 `AiRequestContext` 含 metadata、递归深度控制、mcpTools、extensions。`definePlugin()` 为构造助手。

内置插件（exports 子路径 `./built-in/plugins`）：
- `providerToolPlugin.ts:18` — 按 capability(webSearch/urlContext) 查 registry 注入原生 provider 工具；
- `toolUsePlugin/promptToolUsePlugin.ts` — 为不支持 Function Call 的模型提供 XML(`<tool_use>`) prompt 工具调用，配套 StreamEventManager / ToolExecutor / tagExtraction；
- `webSearchPlugin/index.ts` — 各 provider 搜索配置类型。

### 2.4 公共 API（src/index.ts）

`createExecutor / streamText / generateText / generateImage / embedMany`、`isV2Model/isV3Model`、`definePlugin / PluginEngine` 及全部插件与请求类型、类型工具、六个错误类。exports 子路径：`.`、`./built-in/plugins`、`./provider`。

## 3. 渲染层包装（src/renderer/src/aiCore）

- **`AiProvider.ts:27`（~500 行门面类）**：
  - 构造重载 `(model)` / `(model, provider)` / `(provider)`；内部经 `adaptProvider / getActualProvider / providerToAiSdkConfig`（`provider/providerConfig.ts`，HostFormatter 链做 URL 规范化如追加 `/v1`）得到 `{providerId, providerSettings}`；
  - `completions(modelId, params, middlewareConfig):96`：处理 Anthropic OAuth（注入 Claude Code system message）后走 `modernCompletions:137` —— `buildPlugins(...) → createExecutor(...)` → 统一 `streamText` 流式（从不 generateText），经 `AiSdkToChunkAdapter`（`chunk/`）适配为内部 onChunk 回调；
  - 其他：图像生成（Gemini/DashScope 特判）、`models()`(listModels)、`getEmbeddingDimensions()`。
- **`plugins/PluginBuilder.ts:43 buildPlugins()`** 按条件组装插件链：PDF 兼容 → reasoning 抽取(OpenAI/Azure) → simulateStreaming → Anthropic cache → OpenRouter reasoning → DeepSeek DSML parser → Qwen thinking → Gemini3 thought-signature 跳过 → `providerToolPlugin('webSearch'|'urlContext')` → `searchOrchestrationPlugin`(MCP 搜索编排) → `createPromptToolUsePlugin`。
- **`prepareParams/`**：messageConverter、modelParameters/parameterBuilder/modelCapabilities、文件处理。
- **`provider/custom/`**：aihubmix、newapi 定制 provider；**`provider/extensions/`**：应用级扩展注册进包的 extensionRegistry（扩展 `AppProviderSettingsMap` 类型）。
- **`services/listModels.ts` + schemas.ts**：模型列表拉取（schemas 校验）。
- 其余：`tools/WebSearchTool.ts`、`types/`、`utils/`(reasoning 标签解析、dashscope 图像、mcp、websearch)。

## 4. 消息收发全链路

```
Inputbar 输入
→ messageThunk.sendMessage (store/thunk/messageThunk.ts:463, ~1500 行中枢)
   ├─ 组装用户消息/引用/文件/MCP 工具
→ ApiService.fetchChatCompletion (services/ApiService.ts:185)
   ├─ getRotatedApiKey Key 轮换、模型参数构建
→ AiProvider.completions → createExecutor().streamText
← AiSdkToChunkAdapter → ChunkType 回调 (messageStreaming/callbacks/)
← BlockManager 分块写入 newMessage/messageBlock (节流落库 Dexie)
← 完成后 saveMessageAndBlocksToDB、标题摘要 fetchMessagesSummary
```

其他相关 thunk：`resendMessageThunk / regenerateAssistantResponseThunk / loadTopicMessagesThunk / initiateTranslationThunk / throttledBlockUpdate`。

MCP 工具调用：工具名经 `packages/shared/mcp.ts` 的 `buildMcpToolName(serverName, toolName):48` 规范化为 camelCase 函数名；调用经 IPC `Mcp_*` 通道落到主进程 MCPService；不支持 FC 的模型由 promptToolUsePlugin 以 XML 标签协议在文本层完成工具调用。
