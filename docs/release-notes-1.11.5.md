# Cherry-Studio-BB v1.11.5 Release Notes

## 🎯 核心主题：桌面助手挂件新增「天气」TAB

这一版**不新增依赖、不改数据库结构**，用户数据（聊天记录 / 助手 / 模型配置 / 知识库 / 便签 / 待办 / 闹钟 / 打卡）**完全兼容**，覆盖安装即可。

主要做了两件事：

1. **给常驻桌面的小挂件加了一个天气页**，位置就在剪贴板左边
2. **顺手做了一次全仓代码体检**：删掉 12 个从不被调用的函数、1 个孤儿常量，合并 3 处逐字相同的重复实现

## 🌤️ 一、新功能：天气 TAB

### 1. 它在哪里

打开桌面助手挂件，顶栏那排图标现在变成 6 个，最左边就是天气：

```
[🌤 天气] [📋 剪贴板] [🎵 本地音乐] [📻 FM 电台] [📝 便签] [☑ 待办]
   ↑ 新增，排在剪贴板左边
```

点一下即可切换。窗口会自动调整到适合天气页的尺寸（380×470），内容多了可以上下滚动。

### 2. 能看到什么

| 区域 | 内容 |
|---|---|
| 当前天气 | 大号温度、体感温度、天气图标与中文名、今日最低~最高、降水概率 |
| 详细数据 | 湿度、风向（八方位）+ 风速、气压、云量、阵风、降水量 |
| 日出日落 | 日出时间、日落时间、紫外线数值 + 强度等级（低 / 中等 / 高 / 很高 / 极高） |
| 未来 5 天 | 星期标签、天气图标、天气文字、温度区间、降雨概率 |
| 空气质量 | PM2.5、PM10、AQI 数值 + 等级（优 / 良 / 轻度 / 中度 / 重度 / 严重污染） |

### 3. 怎么定位城市

**第一次打开**：
- 程序会用你的 IP 大致判断所在城市（只到城市级）
- 不准的话，点右上角的**放大镜图标**，输入城市名即可

**手动搜索**：
- 支持中文输入，例如输入「杭州」
- 同名城市会显示省份区分，例如「杭州 · 浙江」「杭州 · 四川」
- 选中后会**自动记住**，下次打开直接用，不用重新选

**兜底顺序**：上次保存的城市 → IP 定位 → 定位失败则显示北京并提示手动选择

> ⚠️ **IP 定位只到城市级，可能不准**。这是 IP 定位本身的限制（运营商出口 IP 可能归属别处），不是程序问题。手动选一次就能永久记住。

### 4. 数据从哪来（完全免费）

| 用途 | 服务 |
|---|---|
| 天气 + 5 天预报 | Open-Meteo |
| 空气质量 | Open-Meteo Air Quality |
| 城市中文搜索 | Open-Meteo Geocoding |
| 坐标转中文地名 | BigDataCloud |
| IP 粗定位 | ipwho.is |

**全部免费、不需要注册、不需要申请任何 API Key。**

> Open-Meteo 免费额度面向非商业用途（每天 1 万次以内），个人自用完全足够。

### 5. 断网了会怎样

| 情况 | 表现 |
|---|---|
| 天气接口失败 | 显示**上次的数据** + 顶部提示「网络异常」，可点刷新重试 |
| 空气质量接口失败 | 只隐藏空气质量那一行，**不影响主天气显示** |
| 地名反查失败 | 直接显示经纬度，不阻塞天气 |
| 请求太慢 | 8 秒超时，不会一直转圈 |
| 反复切换城市 | 30 分钟内同一城市走缓存，不重复请求 |

### 6. 隐私说明

- **天气面板第一次点开才会联网**。你不点它，程序不会发起任何定位或网络请求
- IP 定位会把你的 IP 发给 `ipwho.is`；如果你不想暴露，可以只用「手动搜索城市」，不要点「使用当前位置」

### 7. 技术实现（给开发者）

**新增文件** `src/renderer/src/widgets/music/weather/`：

| 文件 | 职责 |
|---|---|
| `WeatherView.tsx` | 天气视图（纯 React + CSS 类，与挂件其余视图风格一致，不使用 antd） |
| `api.ts` | 五个接口封装、数据归一化、超时、缓存、城市持久化 |
| `weatherCodes.ts` | WMO 天气码 → 中文/图标、AQI 与紫外线分级、风向、日期标签 |
| `__tests__/` | 47 个单元测试 |

**修改文件**：

| 文件 | 改动 |
|---|---|
| `src/renderer/musicWidget.html` | `connect-src` 精确放行 5 个天气接口域名 |
| `widgets/music/MusicWidgetApp.tsx` | `View` 类型与 `VIEWS` 数组加入 `weather` 并置于首位；延迟挂载；窄窗口 tab 自动滚入可见区 |
| `widgets/music/music.css` | 新增 `.wx-*` 样式约 400 行（使用挂件既有 CSS 变量，亮/暗主题自适应） |

**几个关键设计点**：

- **CSP 精确放行**：只增加需要的 5 个域名，其余安全策略不变
- **延迟挂载**：天气组件首次切到该 tab 才创建，避免挂件启动即定位
- **竞态保护**：`requestId` + `alive` 双保险，快速切城市时旧响应不会覆盖新城市
- **跨午夜正确**：以接口 `timezone=auto` 返回的**目标城市当地日期**判定「今天」，顶部卡片与列表不会错位
- **失败回滚**：切换城市失败时回滚标题，且**只有成功取到数据才保存城市**，不会持久化坏城市

### 合并 3 处逐字相同的重复代码

**问题**：主窗口、快捷助手、划词动作窗口各自是独立的渲染进程，每个入口都写了一份**一模一样**的「自定义 CSS 注入」逻辑（11 行 × 3 份）。

**修复**：抽取为 `src/renderer/src/utils/window.ts` 的 `applyUserCustomCss(css)`，三处改为调用。

**行为完全等价**：先移除旧的 `<style id="user-defined-custom-css">` 节点，再判断为空则返回（不注入空标签），否则写入新样式。

净减少约 33 行重复代码。

## 🔍 三、核实后「刻意不处理」的项目

做清理时也查了不少「看起来该删」的东西，但核实后**没有动**，理由如下：

| 项目 | 核实结果 |
|---|---|
| `jest-styled-components` 依赖 | ❌ **有用**，被 `tests/renderer.setup.ts` 引用做快照序列化 |
| 18 个「未被导入的模块」 | ❌ 全是误报（动态 `import()`、路径别名、HTML 直接加载的入口、测试基础设施） |
| `utils/select.ts` 的 15 个同名函数 | ❌ 是 TypeScript **函数重载**声明，不是重复代码 |
| `selectPendingPermission` 等 5 个函数 | ❌ **不能删**，分别被测试 mock、其他用例的状态清理、测试用缓存重置依赖 |
| 25 个未被引用的图片（约 0.32MB） | 可能是品牌素材，删除不可逆，**按保守原则保留** |
| 6 处 TopView 弹窗样板 | 属项目既定写法，抽取需改动弹窗基础设施，**风险高于收益** |
| paint / video 两套页面的相似逻辑 | 相似但不等同，**强行合并会引入耦合** |
